# 🦅 Phoenix Guardian — نگهبان فونیکس

نگهبان ۲۴/۷ پلتفرم [ترمینال تحلیل و سیگنال فیوچرز کریپتو](https://j1std7368na1-d.space-z.ai) روی زیرساخت رایگان GitHub Actions.

## چه می‌کند؟ (هر ۵ دقیقه به‌صورت خودکار)

۱. **چک سلامت** — `GET /api/cron?src=github` — پینگ در آمار پلتفرم ثبت می‌شود و موتور تحلیل در صورت خواب، خودترمیمی می‌شود
۲. **بیدارسازی سرتاب سرد** — اگر پاسخ نداد: ۳ پینگ پیاپی اضطراری (خودِ GETها سندباکسِ خفته z.ai را بیدار می‌کنند)
۳. **احیای رسمی** — اگر بالا نیامد: فراخوانی API ری‌استارت workspace در z.ai (نیازمند `ZAI_TOKEN`)
۴. **هشدار تلگرام** — اگر هنوز پایین بود: پیام با لینک بیداری دستی + یادآوری هر ۳۰ دقیقه تا بازگشت
۵. **ثبت وضعیت** — `guardian-state.json` در همین ریپو commit می‌شود — همین فایلی که پنل «انتشار ۲۴/۷» پلتفرم به‌صورت زنده می‌خواند

## Secretها (Settings ← Secrets and variables ← Actions)

| نام | مقدار | وضعیت |
|---|---|---|
| `PLATFORM_URL` | `https://j1std7368na1-d.space-z.ai` | ✅ تنظیم شده |
| `TG_BOT_TOKEN` | توکن ربات تلگرام | ✅ تنظیم شده |
| `TG_CHAT_ID` | شناسه چت تلگرام | ✅ تنظیم شده |
| `ZAI_CHAT_ID` | شناسه چت z.ai | ✅ تنظیم شده |
| `ZAI_TOKEN` | توکن z.ai | ⬜ **اختیاری** |

> بدون `ZAI_TOKEN` هم نگهبان کامل کار می‌کند (پینگ + بیدارسازی با GET + هشدار تلگرام)؛ فقط «احیای رسمی» غیرفعال می‌ماند.
> برای فعال‌سازی آن: چت z.ai را در مرورگر باز کنید ← `F12` ← تب **Application** ← **Local Storage** ← `chat.z.ai` ← کلید `token` ← مقدار را کپی و در Secret با نام `ZAI_TOKEN` ذخیره کنید.

## نحوه مشاهده

- تب **Actions** ← اجرای **Phoenix Guardian** ← لاگ کامل چرخه
- فایل [`guardian-state.json`](guardian-state.json) — آخرین وضعیت (up/down + رخدادها)
- پنل پلتفرم ← تب «انتشار ۲۴/۷» ← بخش نگهبان فونیکس ← آدرس همین ریپو را وارد کنید

## تست دستی

Actions ← **Phoenix Guardian** ← **Run workflow** ← تیک **notify_test** ← Run — یک پیام آزمایشی به تلگرام می‌رسد و چرخهٔ نگهبانی هم اجرا می‌شود.

## نکته‌ها

- زمان‌بندی `*/5` در GitHub Actions گاهی تا ~۱۵ دقیقه تأخیر دارد (رفتار عادی GitHub؛ لایه‌های دیگر پلتفرم پوشش می‌دهند)
- کامیت‌های `phoenix:` را خودِ نگهبان انجام می‌دهد — این کامیت‌ها ریپو را همیشه «فعال» نگه می‌دارند تا GitHub زمان‌بندی را غیرفعال نکند
- `guard.sh` نسخهٔ خام اسکریپت نگهبان است؛ `phoenix-guardian.yml` از روی آن تولید می‌شود (فایل یگانهٔ در حال اجرا همان YML است)
